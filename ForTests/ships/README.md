# ForTests Ships

The shipyard is moving to a component-first architecture. Every vessel owns its
geometry algorithms and its component assembly plan; the shared folder remains
limited to low-level editor lifecycle and definition/override support.

## Component-first pilot vessels

The first five vessels have been migrated into independent folders:

- `barque/`
- `brig/`
- `brigantine/`
- `caravel/`
- `carrack/`

Each folder contains:

- `architecture/layout.js`: coordinate convention, component mount points,
  assembly order, dependency graph, and the vessel's mast stations/scale factors.
- `architecture/hull-geometry.js`: that vessel's own deck-height, keel-depth,
  half-breadth and hull-section equations.
- `generators/`: independent builders for hull, keel, stem, decks, deck and
  hull planking, frames, stern, cabins, bow, steering, fittings, anchors,
  sails, mast instances and standing rigging.
- `<vessel>.js`: the vessel facade and architecture-driven assembler.

Every mast instance has a small dedicated entry module (foremast, mainmast,
mizzenmast, etc.). The ship-specific mast frame generator produces the
individual mast geometry, yards, sails and related parts; the architecture
selects each mast instance and supplies its own station and scale parameters.
Standing rigging is generated by a separate ship-specific component generator.

The remaining eleven vessels are intentionally unchanged and continue to use
their existing flat modules directly inside `vessels/`. The registry supports
both layouts during this pilot so the preview remains usable throughout the
migration.

## Shared support

The `shared/` directory contains only editor/support infrastructure:

- `ship-editor-kit.js`: generic Three.js primitives/materials, editable
  component API, state save/restore, sail animation hooks and cleanup. It
  contains no vessel geometry algorithms.
- `vessel-definition.js`: validation, metadata derivation and per-vessel
  editor overrides. A vessel may declare its editor module path.

There is no shared hull, cabin, mast, rigging or sail geometry engine. New
component geometry belongs inside its owning vessel's folder.

## Extending a vessel

To add or replace a component on a migrated vessel, add or modify its
ship-specific generator and update `architecture/layout.js` if its mount,
dependency or assembly order changes. The assembler invokes the ordered
components and exposes the chosen architecture on the resulting model as
`userData.shipArchitecture`.

The component split is intended to make individual parts easier to regenerate,
replace, inspect and customize. It does not claim that these generated meshes
are museum-scanned CAD models or exact surviving lines plans.
